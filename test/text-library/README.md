## 文件分工

- [manifest.json](manifest.json)：枚举六份输入、原作者、语言、来源、处理记录、文件字节数和 SHA-256。路径相对于本目录解析。
- `texts/`：六份 UTF-8/LF 正文。模型输入只能来自清单的 `books[].filename`；文件名和书名也不能作为补写书外知识的依据。
- [reference/source-manifest.json](reference/source-manifest.json)：旧清单的原样副本，包含逐章范围和参考章数，只用于评测。里面的 `books[].filename` 仍以本目录为基准；历史 `source_archive_directory` 等路径只在来源仓库中解析。
- [provenance/NOTICES.md](provenance/NOTICES.md)：来源提交、许可与资料映射；其余文件保留原有署名、来源说明、下载信息及历史复核资料。

`reference/`、`provenance/` 和本说明都不得拼入模型输入。下载底本可能含目录、其他篇目和许可文字，不是额外的测试小说。

## 地址与内容约束

参考清单中的章节位置是 UTF-8 解码后的 Unicode 码点下标，从零开始，结束位置不包含在范围内；不是 UTF-8 字节位置，也不是旧业务管线的 UTF-16 地址。后续业务协议需要显式转换，不能直接混用。

原文本已经过来源整理：去除网页导航或电子书页眉页脚、部分固定宽度折行合并；个别章题从插图中取出或统一格式。具体操作保留在清单与来源说明中。这些样本可验证中英文及不同长度，但不能单独证明原始排版、OCR、任意语言或任意新书的泛化效果。

## 后续评估约定

当前有章节参考，没有逐项实体提及和身份关系的人工金标准。旧库历史成功或失败记录不作为新库验收结果，不能把模型输出直接当标准答案。

后续应分别评估：

1. 实体发现：漏掉多少应保留的提及，错提多少，原文范围是否正确。
2. 候选检索：应该送去比较的同一身份提及，是否进入待比较集合；未入选的提及仍须保留。
3. 身份判断：同一、不同和证据不足的判断，以及错误合并和错误拆分。
4. 完整流程：按书记录耗时、实际模型输入输出量、请求／重试次数、缓存命中和未完成范围。

人工标注应覆盖中文、英文、短篇、长篇中的同名异人、无姓名称谓、跨章别名和低频对象。用于修改规则／提示词的样本与最终检查样本要分开；长篇至少按整章保留未用于调参的部分，后续补充整本未见作品。不得为这六本书硬编码人名、身份答案、章节数或位置。

首轮设计仍在讨论：生成式模型负责开放式发现，本地程序保存并核验原文，检索阶段提供可能相关的记录，决策模型判断身份关系；具体模型、语言和检索实现尚未选定或实现。
