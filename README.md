# EntityTrace · 实体溯源

EntityTrace 希望把小说等文本中的人物、地点、物品及其他实体整理成结构化数据，并让每个结果都能追溯到原文位置、证据和具体判断。

这是独立命名的本机后端工具项目，首版以 JSON 文件交付结果。人工审核通过智能体对话或待回答清单完成；不建设前端，暂不使用 Docker。

## 预期用途

1. 导入原文，保留来源版本和可校验的位置。
2. 按章节组织处理，发现具体提及，判断哪些称呼属于同一个实体。
3. 保存原文证据、模型决策及人工修正，便于查错和重算受影响的结果。
4. 导出实体数据、决策记录、审核清单和处理覆盖情况。

原始提及、身份归属、证据和修正分别记录，名称匹配或模型高分不直接当作身份事实。

## 当前能力

六份中英文小说测试资料已建立，业务流程仍在设计讨论中。**尚无可运行的实体处理程序、数据库或模型调用入口，也没有性能与准确率基准。**

## 测试资料

已引入《伤逝》、The Adventure of the Second Stain、《九命奇冤》、Pride and Prejudice、《水浒传》120 回本和 Moby-Dick，覆盖中英文、独立短篇及不同长度的长篇。

正文保持来源版本字节，来源与许可随资料保存。模型输入与章节参考答案分开；当前没有逐项实体或身份的人工标准答案，不能将资料迁移视为模型验收通过。输入列表见 [测试清单](test/text-library/manifest.json)。
