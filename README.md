# EntityTrace · 实体溯源

从文本中提取结构化实体，让每个结果都能追溯到原文位置、证据和具体决策。

这是独立命名的新项目。首版聚焦本地后端和 JSON 交付，不建设前端，不要求 Docker，不复制旧工程及其运行环境。

## 当前状态

2026-10-28 已建立本地 Git 仓库和 GitHub 私有仓库。当前只有项目定位与设计起点，尚未实现地址索引、实体提取或模型调用，没有性能基准。

## 首版目标

1. 导入原文，保存不可变的来源版本与可校验地址。
2. 分块发现实体提及，保留原文证据及未确定候选。
3. 用明确的决策问题处理身份同一性、分类及事实支持关系。
4. 输出实体 JSON、逐项决策记录、待回答清单和覆盖情况。
5. 人工答案单独留档，只重算受影响的结果。

名称、类别和摘要是结果；原文提及、证据、模型裁决和人工修正分别保存，不相互覆盖。

## 数据与索引的设计起点

采用原文不可变、处理单位可恢复、结果增量保存、计算与存储分开的思路。第一版拟采用本地文件加 SQLite，由数据库实现有序索引，不自行开发 B+ 树或分布式存储系统。开发语言、具体表结构与索引需要结合首个原型验证后确定。

| 数据 | 应保存的内容 | 典型访问方式 |
| --- | --- | --- |
| 原文版本 | 原始文件、文件哈希、编码；派生文本另存版本及映射 | 按来源版本读取 |
| 原文片段 | 稳定 ID、来源版本、起止位置、坐标单位、片段类型 | 按来源和位置顺序／范围访问 |
| 实体提及 | 名称、具体出现位置、来源发现 ID；未定位状态显式保留 | 按规范化名称召回候选，按原文位置取证 |
| 身份与归属 | 实体 ID、提及成员、合并／拆分依据和版本 | 按实体查全部出处 |
| 决策与人工答案 | 问题、选项、实际证据、模型／规则版本、概率、confidence、最终动作、上游依赖 | 按决策回溯、按依赖找受影响结果 |
| 处理单位 | 输入及配置指纹、状态、结果引用、耗时和重试 | 找未完成单位、恢复处理 |

有序索引候选包括 `(source_id, start_position)`、`(entity_id, source_id, start_position)`、`(normalized_name, source_id)`；最终键顺序以真实查询计划验证。名称匹配仅用于召回，不代表同一身份。

SQLite 使用表 B-tree 与索引 B-tree 等结构，不能将所有 SQLite 索引笼统称作严格的 B+ 树。这里采用的是成熟数据库提供的有序索引能力。

## 地址约束

- 地址必须绑定确定的原文版本，并明确 `[start, end)` 半开区间和 `offset_unit`。
- UTF-8 字节、Unicode 码点和 UTF-16 单位不可混用。旧项目的 UTF-16 地址不能直接传给文件字节读取。
- 按需读取原文可采用 UTF-8 字节地址，或为已有逻辑坐标建立字节映射；需要先用中文、英文、补充平面字符、BOM 和 CRLF 验证，再固定协议。
- 改字、清洗、换行调整产生新版本及映射，不静默改变既有证据地址。
- 不重叠处理块可用前驱定位与顺序扫描。任意重叠片段不能仅凭起点索引就承诺最优区间查询复杂度，应单独评估。
- 处理分块和原作章节是不同概念；机械分块不冒充原文章节。

## 提速与回溯

索引主要减少取证、检索和结果重建成本；模型等待仍需通过减少无必要输出、共享上下文合批、有限并发及复用有效结果来优化。

模型调用在数据库事务外进行，完成后用短事务保存。SQLite 同时只能有一个写入者，网络请求并发不等于数据库无限并发写入；首版可由一个写入队列统一归档。

每项决策需要保存来源、问题及规则版本、输入证据、完整概率分布、执行动作和依赖。confidence 不直接等同于实测正确率；漏提对象也不会自动产生低置信度记录。

建议交付 `result.json`、`decisions.jsonl`、`review.json` 和 `manifest.json`。未处理范围和待审结果显式标记，不能伪装成全部完成。文件名与字段仍属于设计建议，尚无可执行导出入口。

## 第一个验证点

先验证“原文导入 → 地址入库 → 按位置取原文 → 来源完整性校验”这条闭环，检查实际查询计划和读入字节量。随后接候选发现、决策、审核答案与 JSON 导出。计时分开记录索引访问、模型等待、保存、恢复和人工等待，不预先承诺加速倍数。
